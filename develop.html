2 · 改内容

主页所有内容都在 index.html 里，没有数据文件、没有模板引擎—— 想加一条就复制一段现成的、改里面的字。下面每种条目给一份可直接粘贴的模板。

通用做法

先在 index.html 里搜索定位（比如搜 id="papers"）， 复制一整个 <div class="paper">…</div> 块，粘在它下面，再改文字。 顺序就是显示顺序，想调整位置直接剪切粘贴整块。

加一篇论文

位置：搜 id="papers"。整块复制下面这段，放在最后一个 <div class="paper"> 后面：

<div class="paper">
  <div class="paper-id">2601.12345</div>
  <div>
    <h3><a href="https://arxiv.org/abs/2601.12345" target="_blank" rel="noopener">论文标题写这里</a></h3>
    <p class="paper-note"><span data-en>One-line English summary.</span><span data-sep> · </span><span data-zh lang="zh">一句话中文摘要。</span></p>
  </div>
  <div class="paper-meta">q-fin.PR · 2026</div>
</div>

三个格子分别是：左边 arXiv 编号、中间标题 + 摘要、右边分类和年份。 第一条的顶部金线和最后一条的底线是 CSS 自动加的 （.paper:first-of-type / :last-of-type）， 所以不管你加在哪、删掉哪一条，边框都会自己接上，不用手动调。

加一个项目

位置：搜 id="research"。模板：

<div class="proj">
  <div class="proj-num">07</div>
  <div>
    <h3 data-en>English project title</h3>
    <p class="en" data-en>English description, two or three lines.</p>
    <p class="zh" data-zh lang="zh">中文描述，两三行。</p>
    <div class="tag-row"><span class="tag tag-outline">PyTorch</span><span class="tag tag-outline">CUDA</span></div>
  </div>
  <div class="proj-meta">右边的状态说明</div>
</div>
这里有个坑

01 02 03… 这些编号是手写死的，不会自动重排。 删掉第 3 条，剩下的就变成 01 02 04 05 06。加减项目后记得从上到下把 <div class="proj-num"> 里的数字重编一遍。 （第一条编号自动变成金色，这个不用管。）

加一段学历 / 一个研究方向

这两处都用同一个三栏容器 <div class="split">（栏宽和分割线规则完全一样）， 但栏内结构不同，模板不能互换。往容器里加一个 <div> 就是加一栏。

学历（搜 id="education"）——标题用 h3：

<div>
  <h3>学校名 University</h3>
  <p class="plain"><span data-en>M.S., Something</span><span data-sep> · </span><span data-zh lang="zh">某某硕士</span></p>
  <p class="courses">课程一 · 课程二 · 课程三</p>
  <p class="place">City, Country</p>
</div>

研究方向（页面上第一个 <div class="split">）——标题用 h2， 中文标题是单独一行 .split-zh-title，正文分 .en / .zh 两段： 

<div>
  <h2 data-en>English direction title</h2>
  <div class="split-zh-title" data-zh lang="zh">中文方向名</div>
  <p class="en" data-en>English description.</p>
  <p class="zh" data-zh lang="zh">中文描述。</p>
</div>
别把学历模板粘到研究方向里

粘错了不会报错，但会静默出两个问题：标题变成 23px（h3 而不是 25px 的 h2）， 而且裸 <h3> 没有 data-en，切成「中」的时候英文标题不会隐藏。

栏与栏之间的竖分割线是 CSS 自动加的（.split > * 加左边框、 :first-child 清掉），所以减到两栏没问题。

想加第四栏的话

竖线规则只对「排在同一行」的栏成立。三栏在约 834px 以下就排不下会折行， 所以 site.css 里专门有一条 @media (max-width: 840px) 抢在折行之前把竖线换成横线。加到四栏，折行点会往上移到 1100px 左右， 那条 840px 就不够用了——折到第二行的那栏会拖着一条无处安放的竖线。 真要加第四栏，把那个 840px 改成 1120px 即可。

加一行技能

位置：搜 class="skills"。这是个 <dl>，一行 = 一对 dt + dd：

<dt><span data-en>Category</span><span data-sep> · </span><span data-zh lang="zh">分类名</span></dt>
<dd><span class="tag tag-outline">工具一</span><span class="tag tag-outline">工具二</span></dd>

加减多少行都行，左列固定 190px 宽，标签自动换行。

改首页那四个数字

位置：搜 class="stats-row"。每个数字是这样一块：

<div>
  <p class="stat-num">400×</p>
  <p class="stat-label"><span data-en>GPU speedup</span><span data-sep> · </span><span data-zh lang="zh">GPU 加速比</span></p>
</div>
改数量要同时改 CSS

这一排是写死四列的。想改成三个或五个，要去 assets/site.css 搜 .stats-row，把 repeat(4, minmax(0, 1fr)) 里的 4 改掉。 （当初写死是因为双语标签比较长，用自动布局会把第四个挤到第二行。） 想让某个数字变金色，给它加 class="stat-num stat-num-accent"。

加导航链接

位置：index.html 顶部的 <nav>。跳到本页某段用 # 加那段的 id：

<a href="#education"><span data-en>Education</span><span data-sep> </span><span data-zh lang="zh">教育</span></a>

要跳到别的页面就写文件名，比如 href="develop.html"。 导航栏窄屏会自动换行，链接多几个不会挤坏。

3 · 减内容

删一个条目

删论文、项目、学历、技能行，就是把对应的整块 <div>（或 dt+dd 一对）删掉， 不用管边框和分割线，CSS 会自己接上。唯一要手动收尾的是项目编号（见上面那个坑）。

删掉一整段

每个大板块都是一个 <section>，从 <section …> 删到对应的 </section> 即可。删完记得顺手清两样东西：

  1. 导航里指向它的链接——比如删了 id="education" 那段，就把 nav 里的 href="#education" 一并删掉，否则点了跳不动。
  2. 孤立的分割线——页面里有几条 <hr class="rule"> 夹在板块之间。删掉中间某段后可能出现两条紧挨着的横线，删掉其中一条就行。

CSS 里对应的规则可以不删，没有元素用到它们就是几行死代码，不影响任何东西。 真想清干净再去 site.css 里删对应小节（每节都有注释标题，比如 /* ── publications ── */）。

改错了怎么办

改坏了都能退回来，但要分清文件是不是已经在 git 里：

  • 已跟踪的文件，丢掉未提交的修改：git restore 文件名 （老写法 git checkout -- 文件名 也一样）
  • 新加的、还没 git add 过的文件：上面那条会报 did not match any file(s) known to git——这种直接删掉文件即可， git 里本来就没有它的历史
  • 已经提交了才发现不对：git revert HEAD 然后 push

4 · 双语机制

这是全站最容易改坏的地方，动任何文案前先看懂这三个属性：

属性含义选「中」时选「EN」时
data-en英文内容隐藏显示
data-zh中文内容显示隐藏
data-sep两者之间的分隔符 · 隐藏隐藏

所以标准写法永远是三件套，缺一不可：

<span data-en>English</span><span data-sep> · </span><span data-zh lang="zh">中文</span>
  • 只有一种语言的内容（人名、机构名、工具名如 Qiskit）：什么属性都不要加，三种模式下都显示。
  • 整段只有中文：给整个 <p> 加 data-zh lang="zh"，别拆成 span。
  • 忘了写 data-sep：双语模式下中英会直接黏在一起。
  • 忘了写 lang="zh"：中文可能用英文字体渲染，标点间距会怪。

切换逻辑在 assets/site.js，靠 <html data-lang> 上的属性 + CSS 显示/隐藏，选择记在浏览器里。默认是双语。想改默认值，改 site.js 里 read() 函数返回的 'bilingual'。

5 · 改外观

颜色

全站颜色来自 assets/ds.css 顶部的 :root。 改这四个就能换掉整站基调，所有按钮、标签、链接、分割线跟着变： 

--color-bg:      #f3f2f2;   /* 页面底色 */
--color-text:    #201f1d;   /* 正文颜色 */
--color-accent:  #b68235;   /* 主色：链接、按钮、金线 */
--color-divider: color-mix(in srgb, #201f1d 16%, transparent);  /* 所有分割线 */

下面还有 --color-accent-100 到 -900 九档色阶。 实际用到的只有三档：

  • -700——浅底上的强调色，全站 16 处：小标题、论文编号、日期、链接 hover 等
  • -600——链接 hover 色
  • -400——只用了一处：qbitbrief 深色板块的小标题（site.css 的 .qb .kicker）

-200 / -500 / -900 目前没有任何地方在用，改不改都不影响页面。 换主色的话把这一排一起换，不然深浅关系会脱节。

字体

字体在 assets/site.css 最顶上（它覆盖 ds.css 里的默认值）： 

:root {
  --font-heading: "Cormorant Garamond", "Noto Serif SC", serif;  /* 标题 */
  --font-body:    "Lora", "Noto Serif SC", serif;                /* 正文 */
}

英文字体从 ds.css 第 2 行的 Google Fonts 加载， 中文的 Noto Serif SC 从每个 HTML 文件 <head> 里加载。 换字体要同时改这两处：变量名 + 对应的 Google Fonts 链接， 否则会静默回退到系统字体。

间距与布局

页面内容最宽 1200px（site.css 里的 .wrap）。 大部分板块的上下留白直接写在 index.html 那个 <section> 的 style="padding:…" 上—— 这是从设计稿逐像素搬过来的，改之前想清楚。

有三个例外，改 HTML 没用

首屏、数字条、qbitbrief 深色板块的留白在 CSS 里，不在 HTML 上—— 分别是 site.css 的 .hero、.stats、.qb-inner 的 padding。在 index.html 上给它们加 style="padding:…" 会被 CSS 覆盖，静默无效。

四个响应式断点，都在 site.css 最后：

断点发生什么
900px首屏变单列（照片移到文字下方并缩小）；四个数字先变 2×2；编辑器的右侧栏和实时预览都改成上下堆叠；技能表变单列；导航间距收紧
840px三栏板块（研究方向、教育）堆成一列，竖分割线换成横线。这条单独一个断点，原因见上面「想加第四栏的话」
760px论文行、项目行、博客文章行都改成竖排；qbitbrief 的大 Q 水印和留白缩小；文章「上一篇/下一篇」堆成一列；博客搜索框拉满宽、筛选条改左对齐
520px四个数字从 2×2 再堆成一列

6 · 博客与编辑器

文章存在哪

每篇文章只有两种可见性，决定它被写到哪个仓库：

可见性存到谁能看到
公开 Public content/posts.json（本仓库，公开） 所有人。访客一进博客页就静态 fetch 这个文件，不需要登录。删掉之后仍然留在 git 历史里。
私密 Private Junchi-Shen/blog-private 的 posts.json（私有仓库） 只有你。这个仓库不部署、访客的浏览器根本收不到，只能拿你的 GitHub 令牌通过 API 读。
为什么非要开第二个仓库

因为本仓库是公开的。公开仓库里的任何文件，一条 curl 就能读，不需要登录、不需要浏览器，删了也还在 git 历史里。 所以「私密文章放公开仓库里但界面上不显示」等于没有私密——UI 只是没画出来， 字节照样发给了每一个访客。私密文章必须待在另一个私有仓库，这条没有折中余地。

发布流程

静态站的 JS 写不了文件，所以「浏览器 → 仓库」这一步需要一座桥。有两条路，任选：

  1. 浏览器直连（默认）——列表页的「连接 GitHub」里粘一个 fine-grained token（只授权那两个仓库、只给 Contents 读写），之后点 「发布到 GitHub」一键写两个仓库。令牌只存在本机浏览器。
  2. 不想在浏览器放令牌——点「导出 JSON」，然后 node tools/publish.mjs。脚本自己拆分公开/私密、写文件、commit、push。 私密那半需要先把 blog-private 克隆成本项目的同级目录。

两条路都有同一道硬检查：凡是 visibility 不严格等于 'public' 的文章，一律不允许进 content/posts.json， 检测到就直接报错中止而不是悄悄过滤——能走到那一步说明上游已经坏了， 悄悄过滤只会把 bug 藏起来。没写 visibility 字段的文章一律按私密处理。

本机浏览器的 localStorage 仍然是工作副本（离线也能写），它和仓库按 updatedAt 合并，新的赢，所以在另一台电脑发布过的修改 不会被这台机器上的旧副本覆盖。列表页顶部会显示「本地有改动尚未发布」， 别忘了点发布。

三个视图

blog.html 里三段 <section> 同时存在，靠 JS 加减 hidden 类来切换，同一时刻只显示一个：

id是什么
view-list文章列表、筛选、搜索、导入导出
view-editor写作界面：工具条 + 写作区 + 实时预览 + 右侧栏

改口令

明文只在本机 .env，线上只有哈希。改口令跑这一条：

cd ~/Documents/"Personal Blog"
node tools/set-passphrase.mjs "新口令至少十二位"
git add -A && git commit -m "rotate owner passphrase" && git push

脚本会生成新的随机 salt 和 PBKDF2 哈希写进 assets/auth.js。 别手改 auth.js，也别把明文写进任何会提交的文件。 忘了口令就查 cat .env。

再说一次这个哈希挡不住任何人：静态站没有服务器验密码， 谁都能在控制台改 localStorage 打开作者界面。它的唯一作用是明文不进仓库。 之所以够用，是因为本来就没有东西需要挡——别人的浏览器里是空的。

加一种 Markdown 语法

渲染器是手写的（assets/blog.js 里的 mdRender 和 mdInline）， 只支持用得到的那些。加新语法要改四个地方，漏一个就会不一致：

  1. mdInline（行内语法，如粗体）或 mdRender（块级语法，如列表）——加解析规则
  2. assets/site.css 里 .article-body 那一节——加对应样式
  3. blog.html 编辑器底部那行 class="editor-hint" 的提示文字——让自己记得住
  4. blog.js 里 excerpt() 的剥除正则 .replace(/[#>*`~-]/g, '')——把新符号加进这个字符类。 最容易漏的一个：漏了不会报错，只是列表页摘要里会露出原始符号 （只影响没手写「摘要」的文章）。
安全红线

渲染器先转义、再套标签（esc() 函数），所以正文里写 <script> 只会原样显示出来。加新规则时务必保持这个顺序—— 先把用户文本 esc() 掉，再拼 HTML。反过来就是 XSS。

链接走协议白名单：只放行 http://、https://、mailto: 以及站内相对路径 / 和锚点 #； javascript:、data: 之类一律拒掉，原样显示不渲染成链接。 外链自动带 target="_blank" rel="noopener"。

工具条与快捷键

工具条按钮写在 blog.html 的 <markdown-toolbar> 里， 快捷键映射在 blog.js 搜 HOTKEY_IS_MAC 那一段。 加一个按钮：在工具条里加对应的 <md-xxx> 标签； 加一个快捷键：在那段 keydown 里多一个分支，指向对应按钮。

中文输入法保护：所有键盘处理开头都有 if (e.isComposing || e.keyCode === 229) return;—— 这是防止拼音打字时回车被当成「续列表」拦截。新加键盘逻辑必须保留这一行。

7 · 这些别动

文件为什么真要改的话
assets/ds.css 的组件部分 这是设计稿导出的设计系统原件，是「这个站长什么样」的唯一事实来源。改乱了各页面就会不一致。 只动顶部 :root 变量。要改某个组件在某处的样子，在 site.css 里覆盖。
assets/vendor/markdown-toolbar-element.js GitHub 的第三方组件，打过两个本地补丁（去掉 ESM export 让它免构建加载；斜体 _x_ 改成 *x* 匹配我们的渲染器）。直接下新版会把补丁冲掉，斜体就废了。 升级前先读文件头的注释，重新打一遍那两个补丁。
assets/auth.js 脚本生成的，手改会让 salt 和哈希对不上，直接登不进去。 跑 node tools/set-passphrase.mjs。
blog.html 里的 id 和 data-act JS 全靠它们找元素和分派点击。改个名字就是静默失效——不报错，按钮就是没反应。 要改就 blog.js 里一起改。
.env 口令明文。已经 gitignore 了，永远别提交。 —

8 · 上线与排错

本地预览

改完先在本地看一眼。用 http://，别双击文件用 file:// 打开。

原因不是「file:// 不能用」

实测过：Chrome 在 file:// 下 localStorage 能用、 isSecureContext 是 true、WebCrypto 也正常，作者登录能成功。 真正的坑是 origin 对不上：

  • file:// 和 http://localhost:8765 是两个不同的 origin， 各有各的 localStorage。在其中一边写的文章，另一边看不到，很容易以为文章丢了。
  • 所有 file:// 页面共用同一个 origin（就叫 file://）， 本机任何一个 HTML 文件都在读写同一份 localStorage。
  • 线上是 https://，用 http://localhost 预览才和线上行为一致。

另外各浏览器对 file:// 的宽松程度不一样（上面这组数据来自 Chrome）， 统一用 http:// 就不用操心这些差异。 

cd ~/Documents/"Personal Blog"
python3 -m http.server 8765
# 然后浏览器打开 http://localhost:8765

看完记得关掉：pkill -f "http.server 8765"

上线

cd ~/Documents/"Personal Blog"
git add -A
git commit -m "改了什么"
git push

push 到 main 之后 GitHub Pages 自动构建， 大约 1 分钟后 junchi-shen.github.io 就是新的。没有构建配置、没有 CI、没有别的步骤。

常见故障

现象多半是
线上没变化还在构建，等一分钟；或者浏览器缓存，硬刷新（⌘⇧R）。查构建状态：gh api repos/Junchi-Shen/Junchi-Shen.github.io/pages/builds/latest --jq .status
页面没样式，纯文字CSS 路径写错了。路径都是相对的（assets/…），别改成 /assets/…
中英文黏在一起漏了 <span data-sep> · </span>
切成「中」还是显示英文那段没加 data-en 属性
登不进作者模式口令记错了（查 cat .env）；或 assets/auth.js 没生成——这时会弹「缺少 assets/auth.js」的提示，跑一次 node tools/set-passphrase.mjs
文章不见了换了浏览器 / 清了缓存 / 开了无痕；或者换了地址栏——file:// 和 http://localhost 是两个 origin，各存各的。只能靠之前导出的 JSON 恢复
工具条按钮点了没反应markdown-toolbar 的 for="d-content" 和 textarea 的 id 对不上了
项目编号乱了加减项目后忘了重编 .proj-num（见 §2）

心里有底的几件事

  • 改不坏。所有东西在 git 里，git revert HEAD 就能退回去。
  • 没有依赖。不用 npm install，不用装工具链，换台电脑 clone 下来就能改。
  • 唯一的外部依赖是 Google Fonts。断网时字体回退到系统衬线体，布局不会散。
